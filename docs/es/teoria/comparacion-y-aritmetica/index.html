Carga, comparación y aritmética en KOP y AWL

Cómo se trabaja con números en un autómata: cargar y transferir con L y T, comparar enteros y reales, sumar, restar, multiplicar y dividir, y qué pasa con los bits de estado cuando hay desbordamiento.

Cuadros con EN/ENO en KOP

Comparación (actúan como un contacto: se ponen en serie o en paralelo):

FamiliaCuadros
Comparar INTCMP ==I, <>I, >I, <I, >=I, <=I
Comparar DINT / REALigual con D / R
TransferenciaMOVE (IN → OUT, de 8, 16 o 32 bits)

Aritmética DINTADD_DI, SUB_DI, MUL_DI, DIV_DI, MOD_DI
Aritmética REALADD_R, SUB_R, MUL_R, DIV_R, ABS, SQR, SQRT, EXP, LN, SIN, COS, TAN, ASIN, ACOS, ATAN
ConversiónBCD_I, I_BCD, BCD_DI, DI_BCD, I_DI, DI_R, ROUND, TRUNC, CEIL, FLOOR, INV_I, INV_DI, NEG_I, NEG_DI, NEG_R
Lógica de palabrasWAND_W, WOR_W, WXOR_W, WAND_DW, WOR_DW, WXOR_DW

  • ENO = 0 si EN = 0 o si hubo un error. Por ejemplo, ADD_I con desbordamiento o I_BCD fuera de ±999.
  • Los cuadros se pueden encadenar: ENO de uno → EN del siguiente.
  • No existe I_R: para pasar de INT a REAL hay que usar I_DI y después DI_R.

Carga y transferencia

InstrucciónEfecto
L opACU2 := ACU1; ACU1 := op. Un byte o una palabra se cargan en la parte baja de ACU1 y el resto se rellena con ceros (sin extender el signo)
T opop := parte baja de ACU1 (1, 2 o 4 bytes según el operando). Se ejecuta siempre, sea cual sea el RLO. No modifica los acumuladores
LC T n / LC Z nCarga en BCD el valor de un temporizador o contador
L STW / T STWLee o escribe la palabra de estado
L DBNO / L DBLGNúmero / longitud del DB abierto
      L     MW 10           // ACU1 = MW10              ACU2 = (anterior)
      L     MW 12           // ACU1 = MW12              ACU2 = MW10
      +I                    // ACU1 = MW10 + MW12       ACU2 = MW10 (con 2 ACU no cambia)
      T     MW 14           // MW14 := ACU1-L

T es incondicional. Para transferir solo si se cumple una condición hay que saltar por encima: U E0.0 / SPBN NO / L 5 / T MW10 / NO: NOP 0.

Ceros, no signo. L MW 10 con MW10 = −1 (W#16#FFFF) deja ACU1 = DW#16#0000FFFF. Para tratarlo como DINT hay que usar ITD.

Bits de estado tras +I (las demás operaciones INT y DINT siguen la misma idea):

Ejemplo: 30000 + 10000 → se guarda −25536, con OV = 1 y OS = 1.

  • División por 0: A1 = A0 = 1, OV = OS = 1. El resultado no es válido.
  • REAL: un resultado infinito pone OV y OS a 1. Un resultado no válido (NaN) pone además A1 = A0 = 1.

Comparación

==I, <>I, >I, <I, >=I, <=I comparan ACU2 con ACU1: L a / L b / >I significa "a > b". Las variantes …D comparan DINT y las …R comparan REAL.

  • El resultado (1 o 0) se escribe en el RLO y sustituye al anterior: no se combina con él. Para usarlo en serie con contactos hay que meterlo entre paréntesis:
      U     E 2.0
      U(
      L     MW 30
      L     500
      >I
      )
      =     A 5.6           // A5.6 = E2.0 ∧ (MW30 > 500)
  • La comparación también pone A1/A0 (ver Registros de la CPU), pone OV = 0 y deja /ER = 1. La cadena puede continuar con U, O...

Ejemplos resueltos

E20Comparación de nivel

Enunciado: MW30 = nivel en litros.

  • A5.4 = nivel alto (> 500).
  • A5.5 = nivel bajo (< 100).
  • A5.6 = alarma de nivel alto, solo si E2.0 (habilitación) = 1.

Conceptos: la comparación sustituye el RLO, así que para combinarla con un contacto va entre paréntesis.

      L     MW 30
      L     500
      >I
      =     A 5.4
      L     MW 30
      L     100
      <I
      =     A 5.5
      U     E 2.0
      U(
      L     MW 30
      L     500
      >I
      )
      =     A 5.6

E21Suma con detección de desbordamiento

Enunciado: MW44 = MW40 + MW42. M1.0 = hubo desbordamiento en esta suma. M1.1 = memoria de desbordamiento (se borra con E0.0).

      L     MW 40
      L     MW 42
      +I
      T     MW 44
      U     OV
      =     M 1.0
      U     OS
      S     M 1.1
      U     E 0.0
      R     M 1.1

E22Multiplicación y división entera (cociente y resto)

Conceptos: *I deja un DINT en ACU1. /I deja el cociente en ACU1-L y el resto en ACU1-H.

      L     MW 50
      L     MW 52
      *I
      T     MD 54       // producto completo (32 bits)
      L     MW 50
      L     MW 52
      /I
      T     MW 58       // cociente
      SRD   16          // trae el resto (ACU1-H) a la parte baja
      T     MW 60       // resto

Ponte a prueba

Piensa la respuesta antes de abrir la solución.

Q03¿T depende del RLO?

Con E0.0 = 0, ¿cuánto valen MW30 y A4.0?

      U     E 0.0
      L     5
      T     MW 30
      =     A 4.0
Solución

MW30 = 5 (T es incondicional) y A4.0 = 0 (L y T no tocan el RLO).

Preguntas frecuentes

¿Qué pasa si una suma de INT se sale de rango?

El resultado da la vuelta: 30000 + 10000 deja −25536 en el acumulador y se activan los bits de desbordamiento OV y OS. La CPU no se para.

¿Depende la instrucción T del RLO?

No. L y T se ejecutan siempre, valga lo que valga el RLO. Para transferir solo cuando se cumple una condición, hay que saltar por encima con SPBN.

¿Qué deja /I en el acumulador?

El cociente en la parte baja (ACU1-L) y el resto en la parte alta (ACU1-H). Por ejemplo, L 17 / L 5 / /I deja 3 abajo y 2 arriba.

¿Por qué una comparación en serie con un contacto va entre paréntesis?

Porque la comparación sustituye el RLO, no se combina con él. Dentro de U( … ) se calcula aparte y después se combina con el contacto.
