Bloques del programa: OB, FC, FB y DB

Cómo se estructura un programa de autómata en bloques: OB de organización, funciones FC, bloques de función FB con su DB de instancia y bloques de datos DB. Los OB más importantes y cómo se llaman los bloques en AWL.

Tipos de bloque

BloqueQué esMemoria propia
OBBloque de organización. Lo llama el sistema operativo: ciclo, arranque, alarmas o erroresTemporales (L)
FCFunción. Código con parámetrosNo: solo temporales
FBBloque de función. Código con parámetros y memoriaSí: un DB de instancia por cada llamada
DBBloque de datos (global o de instancia)Son datos, siempre remanentes
SFC / SFBFunciones y bloques del sistema que vienen en la CPU—
UDTTipo de datos de usuario—

OB importantes

OBCuándo se ejecuta
OB1Cíclicamente (programa principal)
OB10Alarma horaria (fecha y hora)
OB20Alarma de retardo
OB35Alarma cíclica (por defecto cada 100 ms)
OB40Alarma de proceso (flanco en un módulo con alarma)
OB80Error de tiempo (tiempo de ciclo excedido)
OB82Alarma de diagnóstico de un módulo
OB85 / OB86 / OB87Error de ejecución del programa / fallo de bastidor o periferia descentralizada / error de comunicación
OB100Arranque (rearranque completo)
OB121Error de programación (por ejemplo BCD no válido, bloque inexistente)
OB122Error de acceso a periferia

Si ocurre un error y el OB de error correspondiente no está cargado, la CPU pasa a STOP.

Declaración de variables de un bloque

SecciónFCFBPara qué sirve
IN✓✓Parámetros de entrada
OUT✓✓Parámetros de salida
IN_OUT✓✓Parámetros que se leen y se escriben
STAT—✓Variables estáticas: se guardan en el DB de instancia y conservan su valor entre llamadas
TEMP✓✓Temporales: indefinidas al empezar

Llamadas

// FC con parámetros (AWL)
      CALL  FC     1
       Marcha:=E0.0
       Paro  :=E0.1
       Motor :=A4.0

// FB con su DB de instancia
      CALL  FB     1 , DB     1
       Entrada:=E0.2
       Salida :=A4.1

// FC sin parámetros
      UC    FC     2              // llamada incondicional
      U     E      0.3
      CC    FC     3              // llamada condicional: solo si RLO = 1

Cómo se ve un FC genérico en una fuente AWL (un fichero de texto con los bloques; las instrucciones terminan en ;):

FUNCTION FC 1 : VOID
TITLE = Marcha-paro genérico
VAR_INPUT
  Marcha : BOOL ;
  Paro : BOOL ;
END_VAR
VAR_IN_OUT
  Motor : BOOL ;
END_VAR
BEGIN
NETWORK
TITLE = Enclavamiento
      U(    ;
      O     #Marcha;
      O     #Motor;
      )     ;
      U     #Paro;
      =     #Motor;
END_FUNCTION

En KOP una llamada es un cuadro con EN/ENO y los parámetros como patillas.

Fin de bloque y llamadas

InstrucciónEfecto
BEFin de bloque
BEAFin de bloque incondicional
BEBFin de bloque si RLO = 1. Si RLO = 0 sigue, con RLO := 1 y /ER := 0
CALLLlamada con parámetros (ver Llamadas)
UC / CCLlamada incondicional / condicional, sin parámetros

Preguntas frecuentes

¿Qué diferencia hay entre un FC y un FB?

El FB tiene memoria propia: un DB de instancia donde guarda sus variables estáticas (STAT), que conservan el valor entre llamadas. Un FC solo tiene variables temporales, que se pierden al terminar.

¿Qué OB ejecuta el programa principal?

El OB1, que la CPU ejecuta cíclicamente. El OB100 es el arranque, el OB35 la alarma cíclica y el OB80 el error de tiempo.

¿Qué pasa si hay un error y su OB no está programado?

La CPU pasa a STOP. Por ejemplo, un BCD no válido llama al OB121: si el OB121 no está cargado, la CPU se para.
