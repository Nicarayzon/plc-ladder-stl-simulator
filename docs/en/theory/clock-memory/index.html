Clock memory: flashing lights without timers

What a PLC’s clock memory is, how to enable it, the frequency of each bit and how to use it to make a lamp flash or repeat an action every second, with Ladder and STL examples.

Clock memory

Clock memory is a memory byte written by the CPU itself: each of its 8 bits oscillates at a fixed frequency and spends half of the period at 0 and the other half at 1. It is used to make lamps flash and to repeat an action at regular intervals without programming timers.

How to enable it:

  • On the real CPU: CPU properties → Cycle/Clock memory. Tick the box, choose the byte (for example, MB100) and download the hardware configuration.
  • In the simulator: Hardware button → CPU → Ciclo / marca de ciclo (the interface is in Spanish). It uses MB0 by default, but any byte can be chosen.
Bit76543210
Period (s)2.01.61.00.80.50.40.20.1
Frequency (Hz)0.50.62511.2522.5510

With MB100 as clock memory, M 100.5 has a period of 1 s: 0.5 s at 0 and 0.5 s at 1. In other words, it flashes at 1 Hz.

Typical uses:

  • Flashing lamp: the clock memory goes in series with the condition. A I 0.0 / A M 100.5 / = Q 4.0 makes Q4.0 flash at 1 Hz while I0.0 = 1.
  • Two rhythms with the same lamp: slow with M 100.7 (0.5 Hz) for a warning and fast with M 100.3 (2 Hz) for an alarm.
  • Periodic action: M 100.5 gives one rising edge per second. With a counter (CU) you can count seconds, and with FP you can do something once per second.

Watch out:

  • The program must only read that byte. The CPU overwrites it every cycle, so anything the program writes to it is lost. The simulator warns you if the program writes to it.
  • The byte must stay free: do not use it for anything else, not even inside a word (MW 99 and MW 100 include MB 100).
  • It is not suitable for accurate timing: when the condition becomes true, the bit may be halfway through its period, so the first flash can be shorter. For exact delays, use timers (see Timers in Ladder).
  • In the simulator, the byte is updated at the start of each cycle, before the inputs are read. If the clock memory is disabled or the byte is changed, the old byte is set to 0.

Worked examples

Flashing lamp with the clock memory

Task: while the alarm I0.0 is active, the lamp Q4.0 flashes at 1 Hz. The clock memory is in MB100, so M 100.5 (period of 1 s) is used.

      A     I 0.0           // alarm active
      A     M 100.5         // clock memory: 1 Hz
      =     Q 4.0           // flashing lamp

Counting seconds with the clock memory

Task: while I0.3 = 1, counter C2 adds 1 on each rising edge of M 100.5, that is, once per second. I0.4 resets it and MW40 holds the seconds counted. Note that the first second may be counted straight away: it depends on where M 100.5 is in its period when I0.3 turns on.

      A     I 0.3           // count while I0.3 = 1
      A     M 100.5         // one rising edge per second
      CU    C 2
      A     I 0.4           // reset
      R     C 2
      L     C 2
      T     MW 40           // seconds counted

Frequently asked questions

With MB100 as clock memory, which bit oscillates at 1 Hz?

M 100.5, which has a period of 1 s. The periods of bits 0 to 7 are 0.1 / 0.2 / 0.4 / 0.5 / 0.8 / 1 / 1.6 / 2 s.

Can I write to the clock memory byte?

No: the CPU overwrites it every cycle, so anything the program writes is lost. The program should only read it.

Should I use the clock memory or timers for a flashing light?

The clock memory, if one of its frequencies is good for you and it does not matter at which point the flashing starts. Timers, if you need different on and off times or the flashing must start exactly when the condition becomes true (example E17).
