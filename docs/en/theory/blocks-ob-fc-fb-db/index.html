Program blocks: OB, FC, FB and DB

How a PLC program is structured in blocks: organization blocks (OB), functions (FC), function blocks (FB) with their instance DB, and data blocks (DB). The most important OBs, how blocks are called in STL and the library blocks FC 82 and FC 83, which reset or set a range of bits.

Block types

BlockWhat it isOwn memory
OBOrganization block. It is called by the operating system: cycle, startup, interrupts or errorsTemporary data (L)
FCFunction. Code with parametersNo: temporary data only
FBFunction block. Code with parameters and memoryYes: an instance DB for each call
DBData block (global or instance)It is data, always retentive
SFC / SFBSystem functions and system function blocks built into the CPU—
UDTUser-defined data type—

Important OBs

OBWhen it runs
OB1Cyclically (main program)
OB10Time-of-day interrupt (date and time)
OB20Time-delay interrupt
OB35Cyclic interrupt (every 100 ms by default)
OB40Hardware interrupt (edge on a module with interrupts)
OB80Time error (cycle time exceeded)
OB82Diagnostic interrupt from a module
OB85 / OB86 / OB87Program execution error / failure of a rack or distributed I/O / communication error
OB100Startup (complete restart)
OB121Programming error (for example invalid BCD, block that does not exist)
OB122I/O access error

If an error occurs and the corresponding error OB is not loaded, the CPU goes to STOP.

Variable declaration of a block

SectionFCFBWhat it is for
IN✓✓Input parameters
OUT✓✓Output parameters
IN_OUT✓✓Parameters that are read and written
STAT—✓Static variables: they are stored in the instance DB and keep their value between calls
TEMP✓✓Temporary data: undefined when the block starts

Calls

// FC with parameters (STL)
      CALL  FC     1
       Start:=I0.0
       Stop :=I0.1
       Motor:=Q4.0

// FB with its instance DB
      CALL  FB     1 , DB     1
       Input :=I0.2
       Output:=Q4.1

// FC without parameters
      UC    FC     2              // unconditional call
      A     I      0.3
      CC    FC     3              // conditional call: only if RLO = 1

What a generic FC looks like in an STL source (a text file with the blocks; instructions end with ;):

FUNCTION FC 1 : VOID
TITLE = Generic start/stop
VAR_INPUT
  Start : BOOL ;
  Stop : BOOL ;
END_VAR
VAR_IN_OUT
  Motor : BOOL ;
END_VAR
BEGIN
NETWORK
TITLE = Latching
      A(    ;
      O     #Start;
      O     #Motor;
      )     ;
      A     #Stop;
      =     #Motor;
END_FUNCTION

In Ladder a call is a box with EN/ENO and the parameters as pins.

Library blocks: FC 82 (RSET) and FC 83 (SSET)

The standard library brings ready-made blocks that are copied into the project. Two very useful ones are:

BlockSymbolic nameWhat it does
FC 82RSETResets N consecutive bits to 0 in one go
FC 83SSETSets N consecutive bits to 1 in one go

Both have the same parameters:

ParameterDeclarationTypeMeaning
S_BITINPOINTERAddress of the first bit of the range: M 0.0, Q 4.0… It is a pointer, so P#M 0.0 is also valid
NININTHow many consecutive bits: a constant (8) or a word (MW 10)

Typical use: clearing the step memory bits of a GRAFCET in one go when the sequence starts or is reinitialized, instead of one R for each step, and then activating the initial step.

How to bring it into the project: it is copied from the library to the block folder of the program, next to OB1, and downloaded to the CPU with the other blocks. If the CPU has an OB1 that calls FC 82 but does not have FC 82, it goes to STOP when it calls it (block does not exist, OB121 not loaded).

  • In the simulator: book button of the explorer → Converting Blocks ▸ Blocks, and drag FC 82 to the Blocks folder of the project. With the block selected, F1 opens its help. In the project it is protected: its code cannot be seen.
  • In LAD it is also in the catalog, Libraries group: when you place the box in a network, the block is copied to the project.

Call in STL: the parameters go below the CALL, one per line. In the simulator, when you type CALL FC 82 and press Enter, the editor adds the empty parameters.

      A     I 0.0          // reset condition
      JCN   m001           // if it is not met, skip the call
      CALL  FC 82
        S_BIT := M 0.0     // first bit
        N     := 8         // how many bits: M 0.0 to M 0.7
m001: NOP   0

It resets M 0.0 to M 0.7, but only in the cycles in which I 0.0 = 1.

In LAD it is a box with EN, S_BIT and N on the left and ENO on the right. To make it conditional, just put the contact before EN.

Watch out:

  • A CALL always runs, in every cycle, without looking at the RLO: without a condition, the bits would be 0 all the time. Make it conditional with a jump (JCN) or, in LAD, with the EN input. Another option is to call it in OB100, which only runs at startup. UC and CC are no use: they only call blocks without parameters.
  • It depends on the MCR (see MCR (Master Control Relay)): inside a disabled MCR zone it changes nothing.
  • If N is 0 or negative, it does nothing. If the range goes beyond the area, the CPU goes to STOP.
  • On return, BR = 1 (in LAD, ENO = 1) and /FC = 0: the next check starts a new chain.
  • The range must not include the clock memory byte (see Clock memory: Clock memory), or it will clear it.

Example with GRAFCET: the initialization push button I 0.0 clears all the steps (M 0.0 … M 0.7) and activates the initial one.

      A     I 0.0          // initialization push button
      JCN   m002
      CALL  FC 82          // clears all the steps
        S_BIT := M 0.0
        N     := 8
      SET
      S     M 0.0          // activates the initial step
m002: NOP   0

Data blocks

      OPN   DB 1            // opens DB1 as the global DB
      L     DBW 0           // DB1.DBW0
      T     MW 10
      A     DB1.DBX 2.0     // full address (it also opens DB1)
      =     Q 4.0

Frequently asked questions

What is the difference between an FC and an FB?

An FB has its own memory: an instance DB where it stores its static variables (STAT), which keep their value between calls. An FC only has temporary variables, which are lost when it ends.

Which OB runs the main program?

OB1, which the CPU runs cyclically. OB100 is the startup, OB35 the cyclic interrupt and OB80 the time error.

What happens if an error occurs and its OB is not programmed?

The CPU goes to STOP. For example, an invalid BCD calls OB121: if OB121 is not loaded, the CPU stops.
