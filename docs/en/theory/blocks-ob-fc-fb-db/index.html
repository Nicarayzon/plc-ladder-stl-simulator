Program blocks: OB, FC, FB and DB

How a PLC program is structured in blocks: organization blocks (OB), functions (FC), function blocks (FB) with their instance DB, and data blocks (DB). The most important OBs and how blocks are called in STL.

Block types

BlockWhat it isOwn memory
OBOrganization block. It is called by the operating system: cycle, startup, interrupts or errorsTemporary data (L)
FCFunction. Code with parametersNo: temporary data only
FBFunction block. Code with parameters and memoryYes: an instance DB for each call
DBData block (global or instance)It is data, always retentive
SFC / SFBSystem functions and system function blocks built into the CPU—
UDTUser-defined data type—

Important OBs

OBWhen it runs
OB1Cyclically (main program)
OB10Time-of-day interrupt (date and time)
OB20Time-delay interrupt
OB35Cyclic interrupt (every 100 ms by default)
OB40Hardware interrupt (edge on a module with interrupts)
OB80Time error (cycle time exceeded)
OB82Diagnostic interrupt from a module
OB85 / OB86 / OB87Program execution error / failure of a rack or distributed I/O / communication error
OB100Startup (complete restart)
OB121Programming error (for example invalid BCD, block that does not exist)
OB122I/O access error

If an error occurs and the corresponding error OB is not loaded, the CPU goes to STOP.

Variable declaration of a block

SectionFCFBWhat it is for
IN✓✓Input parameters
OUT✓✓Output parameters
IN_OUT✓✓Parameters that are read and written
STAT—✓Static variables: they are stored in the instance DB and keep their value between calls
TEMP✓✓Temporary data: undefined when the block starts

Calls

// FC with parameters (STL)
      CALL  FC     1
       Start:=I0.0
       Stop :=I0.1
       Motor:=Q4.0

// FB with its instance DB
      CALL  FB     1 , DB     1
       Input :=I0.2
       Output:=Q4.1

// FC without parameters
      UC    FC     2              // unconditional call
      A     I      0.3
      CC    FC     3              // conditional call: only if RLO = 1

What a generic FC looks like in an STL source (a text file with the blocks; instructions end with ;):

FUNCTION FC 1 : VOID
TITLE = Generic start/stop
VAR_INPUT
  Start : BOOL ;
  Stop : BOOL ;
END_VAR
VAR_IN_OUT
  Motor : BOOL ;
END_VAR
BEGIN
NETWORK
TITLE = Latching
      A(    ;
      O     #Start;
      O     #Motor;
      )     ;
      A     #Stop;
      =     #Motor;
END_FUNCTION

In Ladder a call is a box with EN/ENO and the parameters as pins.

Block end and calls

InstructionEffect
BEBlock end
BEUUnconditional block end
BECBlock end if RLO = 1. If RLO = 0 it carries on, with RLO := 1 and /FC := 0
CALLCall with parameters (see Calls)
UC / CCUnconditional / conditional call, without parameters

Data blocks

      OPN   DB 1            // opens DB1 as the global DB
      L     DBW 0           // DB1.DBW0
      T     MW 10
      A     DB1.DBX 2.0     // full address (it also opens DB1)
      =     Q 4.0

Frequently asked questions

What is the difference between an FC and an FB?

An FB has its own memory: an instance DB where it stores its static variables (STAT), which keep their value between calls. An FC only has temporary variables, which are lost when it ends.

Which OB runs the main program?

OB1, which the CPU runs cyclically. OB100 is the startup, OB35 the cyclic interrupt and OB80 the time error.

What happens if an error occurs and its OB is not programmed?

The CPU goes to STOP. For example, an invalid BCD calls OB121: if OB121 is not loaded, the CPU stops.
